Automasi Ekosistem Hebahan Geran
Serverless Web Architecture

Sistem paparan geran berasaskan pelayar (browser-based) yang membaca data terus daripada Google Sheets tanpa memerlukan pelayan atau App Script.

⚡ Zero Backend

Tiada pelayan diperlukan. Semua logik pemprosesan dijalankan terus dalam pelayar pengguna menggunakan JavaScript.

📊 Smart Priority

Sistem menyusun geran berdasarkan tarikh tutup terdekat secara automatik melalui algoritma sorting client-side.

🎨 Dynamic UI

Paparan web berubah mengikut status tarikh tutup (color-coded indicators) tanpa perlu reload halaman.

Senibina Teknikal
Bagaimana Sistem Berfungsi?
📋

Google Sheets (Pangkalan Data)

Staf memasukkan maklumat geran melalui Google Form → data tersimpan dalam Google Sheets. Helaian ini diterbitkan sebagai CSV awam melalui File → Share → Publish to web.

🌐

Browser Fetch CSV (Client-side JavaScript)

Laman web menggunakan fetch() untuk memuat CSV dari Sheets secara langsung. JavaScript kemudian menghurai (parse) baris CSV, mengira baki hari, dan menyusun geran — semua di dalam pelayar pengguna, tanpa sebarang pelayan tengah.

📁

Google Drive (Lampiran)

Poster (gambar) dan dokumen garis panduan (PDF) disimpan dalam Google Drive. ID fail dimasukkan dalam Sheets dan dipaparkan terus sebagai iframe/pautan dalam laman web.

🏛️

Joomla CMS (Platform Deployment)

Kod HTML/CSS/JS ditanam terus ke dalam halaman Joomla UMS (ums.edu.my/ppp) menggunakan custom Raw HTML editor. Sistem berfungsi sepenuhnya tanpa plugin tambahan atau modifikasi core Joomla — memanfaatkan infrastruktur CMS universiti yang sedia ada.

👤

Paparan Dinamik kepada Pengguna

Penyelidik melihat senarai geran yang telah disusun, boleh dicari, dan dipaparkan dengan warna status. Data dimuatnaik setiap 5 minit secara automatik.

Aliran Kerja
Proses Dari Input Ke Paparan
1

Input Data Terpusat

Staf memasukkan maklumat geran melalui Google Form (nama geran, tarikh tutup, penerangan, pautan poster & dokumen). Data tersimpan terus ke Google Sheets.

2

Penerbitan CSV Automatik

Google Sheets diterbitkan sebagai CSV awam. URL CSV ini dikonfigurasi sekali dalam kod laman web (CONFIG.CSV_URL). Tidak diperlukan sebarang skrip atau API tambahan.

3

Pemprosesan Client-side (JavaScript)

Pelayar memuat CSV, mengurai setiap baris, dan mengira baki hari:

Baki Hari = Tarikh Tutup − Tarikh Hari Ini

Berdasarkan nilai ini, setiap geran diberi status warna:

Status Syarat Warna Border Kad
Buka / Open Baki > 14 hari, atau tiada tarikh 🟢 Hijau
Menghampiri / Soon Baki ≤ 14 hari (termasuk hari ini) 🟡 Emas / Kuning
Ditutup / Expired Baki < 0 (tarikh telah lepas) ⚫ Kelabu
4

Paparan & Kemas Kini Automatik

Geran disusun mengikut keutamaan: yang menghampiri tarikh tutup dipaparkan dahulu; yang sudah ditutup diletakkan paling bawah. Laman web memuat semula data setiap 5 minit secara automatik tanpa perlu refresh oleh pengguna.

📌 Nota Teknikal Penting Sistem ini tidak menggunakan Google App Script atau sebarang backend pelayan. Ia adalah aplikasi web statik (static web app) yang memanfaatkan keupayaan Google Sheets sebagai pangkalan data CSV awam dan JavaScript sebagai enjin pemprosesan — menjadikannya ringan, pantas, dan mudah diselenggara. Sistem ini disebarkan melalui platform CMS Joomla sedia ada universiti tanpa memerlukan hosting berasingan atau konfigurasi pelayan tambahan, menjadikan kos pengoperasian hampir sifar.
Pengurusan Fail
Integriti Fail & Lampiran

Setiap hebahan dijamin mempunyai dokumen sokongan yang disimpan secara sistematik dalam Google Drive dan dipautkan terus ke paparan web melalui ID fail.

🖼️ Poster Visual

Sokongan berbilang poster (dipisahkan dengan koma). Dipaparkan sebagai iframe preview terus dari Google Drive dalam kad geran.

📄 Garis Panduan

Dokumen PDF rasmi untuk rujukan kriteria kelayakan penyelidik. Berbilang fail disokong dan dibuka dalam tab baharu.
